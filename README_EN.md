# FatFishFairy

Embodied intelligence for a big fat blue fish (just kidding).

[中文](README.md) | [English](README_EN.md)

A Windows desktop companion that observes your screen, remembers your interests, and responds to what you are doing.

- **FatFishFairy**: an animated desktop character with a talking bubble that observes continuously.
- **FatFishCli**: a terminal app that runs one observation on a keypress and shows the vision description and fairy response.

Both apps send monitor screenshots to your configured vision model, then ask the fairy model to respond to the description. Memories are saved locally in `memory` and remain available after restarting.

## Prepare and build

You need Windows 10 or later, Git, PowerShell 7, and Visual Studio / Microsoft C++ Build Tools with desktop C++ development components, the **v145 toolset**, and the latest Windows 10 SDK.

```powershell
git clone --recurse-submodules https://github.com/vczh/FatFishFairy.git
Set-Location FatFishFairy
```

For an existing checkout, run `git submodule update --init --recursive`, then `git submodule update --remote Release` to update the GacUI dependency.

Run the following commands in PowerShell 7 from the repository root. First, replace this path with your installed `VsDevCmd.bat`; the setting applies only to the current terminal:

```powershell
$env:VLPP_VSDEVCMD_PATH = 'C:\path\to\Visual Studio\Common7\Tools\VsDevCmd.bat'
```

Before the first build, if `Release/Tools/GacGen.exe` or `Release/Tools/CppMerge.exe` is missing, prepare the resource compiler tools:

```powershell
Push-Location Release/Tools/Executables
& "$PWD/../../.github/Scripts/copilotBuild.ps1" -Configuration Release -Platform x64
Copy-Item ./x64/Release/GacGen.exe, ./x64/Release/CppMerge.exe ../
Pop-Location
```

Then build the apps (or open `FatFish/FatFish.sln` in Visual Studio and build there):

```powershell
Push-Location FatFish
& "$PWD/../Release/.github/Scripts/copilotBuild.ps1" -Configuration Debug -Platform x64
Pop-Location
```

Executables are in `FatFish/x64/Debug/`. Change the parameters to use `Release` or `Win32`; Win32 outputs go to `FatFish/<Configuration>/`. Keep the repository layout intact so the apps can locate configuration, memories, and themes relative to their executables.

## Configure models

Before the first run, create a configuration from the template. If one already exists, edit it without overwriting it:

```powershell
Copy-Item env/apikey-template.json env/apikey.json
```

Edit `env/apikey.json` with details for a service compatible with the OpenAI v1 Chat Completions protocol:

| Field | Value |
| --- | --- |
| `apikey` | Your model service's API key. |
| `url` | An API base URL such as `https://your-server/v1`, or the full `/chat/completions` URL. |
| `auth_header` | For example, `Authorization: Bearer $APIKEY`; `$APIKEY` is replaced with your key. |
| `vision_model` | A vision model ID supporting image input and tool calls. |
| `fairy_model` | A fairy model ID supporting tool calls. |

Git ignores this configuration; do not commit API keys. The offline and local integration tests below do not require real model configuration.

## Use FatFishFairy

```powershell
& ./FatFish/x64/Debug/FatFishFairy.exe
```

- The character stays on top, observes automatically, and speaks in a bubble. The bubble hides when it has nothing to say.
- Hold the left mouse button to drag. Right-click and choose “主题” (Theme) to switch characters, or “退出” (Exit) to close. Position and theme are saved automatically.
- Choose **萝莉小妹抖** (Chibi Maid), **长大的妹抖** (Grown Maid), or **纳垢灵** (Nurgling), each with its own animations and personality. Switching characters starts a new conversation while keeping saved memories.
- The lower-left indicator shows `V` for observation, `F` for a fairy response, or `L` when the screen is unavailable. A trailing number counts failures since the last success.
- Observation pauses while Windows is locked, the remote session is disconnected, or screen capture is unavailable, then resumes automatically when the screen becomes available again. Model errors appear in the bubble and are retried automatically.

Speech is saved in `env/history.md`, and position and theme in `env/config.json`. To adjust a personality, edit its `themes/<theme-folder>/Character.md`.

## Use FatFishCli

```powershell
& ./FatFish/x64/Debug/FatFishCli.exe
```

Press **ENTER** to observe all monitors once and see the vision description and fairy response; press **ESC** to exit. Keys are handled between rounds, and observation does not repeat automatically. If the desktop is unavailable, unlock or reconnect and press ENTER to retry.

The CLI uses the Chibi Maid personality, retains conversation within the current process, and saves memories. Other launch options:

```powershell
# Run one round and exit
& ./FatFish/x64/Debug/FatFishCli.exe --once

# Use env, memory, and themes under another directory
& ./FatFish/x64/Debug/FatFishCli.exe --repo-root 'C:\path\to\FatFishFairy'

# Show options
& ./FatFish/x64/Debug/FatFishCli.exe --help
```

## Test

After building, run offline unit tests. They need no credentials and do not capture the screen or access the network:

```powershell
Push-Location FatFish
& "$PWD/../Release/.github/Scripts/copilotExecute.ps1" -Mode UnitTest -Executable UnitTest -Configuration Debug -Platform x64
Pop-Location
```

Local integration tests capture the screen but connect only to a local fixture service and do not read real credentials. Keep the desktop visible and unlocked; the desktop test moves the mouse:

```powershell
& ./FatFish/UnitTest/Invoke.ps1 -Configuration Debug -Platform x64
& ./FatFish/UnitTest/Invoke-Fairy.ps1 -Configuration Debug -Platform x64
```

See [AGENTS.md](AGENTS.md#unittest-and-verification) for locked-desktop testing and the full development verification procedure.
